## Подготовка

1. `npm ci`, скопировать `.env.example` в `.env`, задать модель и ключ LLM.
2. Положить ответ API организаторов в `data/DEV.json` (массив, records или data.records).
3. Шкалы c04/c06 уже перенесены и сверены со стр. 2 `docs/CQA_Chat_Quality_Checklist.pdf`. Для уже существующего хранилища сохранить исправленный чек-лист новой версией через UI: seed не перезаписывает историю.
4. `npm start`; открыть `/`, роль «оператор». Заранее оценить 2–3 диалога, включая N/A и грубое нарушение.
5. Выбрать диалог с доступным транскриптом и подготовить комментарий к апелляции. Проверить доступность модели и запас времени на её ответ. Не подменять живую оценку записью.

## Репетиция на T+23 (8 ноября, 10:00)

- Получить фактический group_id и сохранить снапшот в `data/<group_id>.json`. Интерфейс читает локальные файлы, автоматической загрузки API организаторов пока нет.
- Запустить пакетную обработку: `npm run eval -- --group <group_id> --checklist default --concurrency 5`. Проверить ошибки и стоимость.
- Пройти сценарий с секундомером; записать фактическое время и ID проверенного диалога.
- Отдельная проверка замены: версия N неизменна; в N+1 старый ID удалён, новый добавлен; повторная оценка использует N+1 и содержит новый ответ. Старые оценки и апелляции остаются привязаны к N.
- Отдельная проверка апелляций: подтвердить без изменения итога; изменить два разных критерия последовательно — финальный итог учитывает оба решения. Пустую причину, запрещённый N/A, число вне шкалы и повторное решение отклонять.
- Проверить RU/KZ/EN, переход к доказательству, истёкшую ссылку на аудио, ошибку LLM и повторный запуск после ошибки.
- До 11:00 зафиксировать проверенный коммит. Выполнение репетиции и загрузка контрольного набора требуют присутствия команды; этот документ не является отчётом об их выполнении.
