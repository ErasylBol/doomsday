# CQA: Conversation Quality Analytics

Прототип оценки качества диалогов поддержки по настраиваемому чек-листу с помощью LLM, с апелляциями и аналитикой для руководителя.

## Запуск
Нужен Node.js 20+.
```bash
npm install
cp .env.example .env   # Windows: copy .env.example .env
npm start              # http://localhost:3000
npm test
```
В `.env` заполнить:
- `CQA_API_URL` — GET-ссылка организаторов (кнопка «Открыть GET для DEV» в задании) **без** `&group_id=...` на конце;
- `LLM_API_KEY` — ключ OpenAI; `LLM_MODEL` и цены `LLM_PRICE_*` уже заполнены для `gpt-6-luna`.

Набор DEV лежит в `data/DEV.json`. Любой другой `group_id` сервер скачивает из API организаторов при первом
обращении и кеширует в `data/<group_id>.json`; «Обновить из API» скачивает заново.

### Контрольный набор (T+23)
1. «Диалоги» → в поле `group_id` ввести выданное значение → «Загрузить» (набор скачается из API).
2. Выбрать чек-лист → «Оценить все». Идёт фоновая задача с прогрессом; 65 диалогов ≈ 1–1,5 мин на `gpt-6-luna`.
3. То же из консоли после загрузки набора: `npm run eval -- --group <group_id>`.

## Модель и стоимость
Провайдер: OpenAI Chat Completions со structured outputs (строгая JSON-схема строится из конфига чек-листа).
Модель: **`gpt-6-luna`**, reasoning_effort `low`, 3 прогона на диалог с голосованием по каждому критерию
(даёт `confidence`). Цены: $0.10 вход / $0.01 кешированный вход / $0.50 выход за 1M токенов.

Замер на всём DEV (65 диалогов, 07.11.2026):
| | Один вызов модели | Одна оценка (3 вызова) |
|---|---|---|
| Входные токены | ≈ 4 800 (≈97% из кеша промпта) | ≈ 14 400 |
| Выходные токены | ≈ 1 050 | ≈ 3 150 |
| **Стоимость** | ≈ $0.0006 | **≈ $0.0018** |

Весь DEV: $0.11 и ≈ 75 с; 1000 диалогов ≈ $1,8. Точнее, но дороже: `LLM_MODEL=gpt-6.1-sol`, `LLM_RUNS=1`
(≈ $0.011 за оценку; цены $2 / $0.1 / $10). Точность на эталонной разметке — `CLAUDE.md`, раздел 5.

## Оценка из консоли
```bash
npm run eval -- --group DEV --limit 5
npm run accuracy
```

Подробности архитектуры и контракта — в `CLAUDE.md`.

Редактор чек-листа: `#/checklists` (каждое сохранение создаёт версию).
Карточка и повторная оценка: `#/list` → загрузить локальную группу → диалог.
Апелляция подаётся из карточки; решение доступно в `#/appeals` при роли «проверяющий».
Роль выбирается в шапке; это демонстрационный переключатель без авторизации.
Снапшот `data/<group_id>.json` должен иметь формат массива, `{records: [...]}` или `{data: {records: [...]}}`.
Новая оценка сохраняет точный номер выбранной версии. Предыдущие оценки остаются в истории.

[Сценарий демо и репетиция на T+23](docs/DEMO.md).
Шкалы c04/c06 сверены со стр. 2 `docs/CQA_Chat_Quality_Checklist.pdf`.

Проверки: `npm test`. Браузерный smoke-тест с отдельным Playwright:
`PLAYWRIGHT_MODULE=/path/to/playwright/index.js CHROMIUM_PATH=/usr/bin/chromium node scripts/browser-smoke.mjs`.
Он использует временный набор и тестовый провайдер, проверяет замену критерия, повторную оценку и апелляцию; реальную LLM не вызывает.
